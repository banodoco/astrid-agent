# T-11: an Agent-owned Composition execution observation boundary

Status: proposed design; no implementation, event, installed render, or qualification. `NEEDS: T-11-AGENT-EXEC-DESIGN design review`.

## 1. Recommendation and limits

Add an optional proof context to the existing host-owned Remotion frame lease. Use the retained Node worker's Browser object to observe the actual rendering page before navigation. Combine V8 precise function coverage, the engine-returned script source, Chromium's frame-to-OS-process trace metadata, a captured webpack input graph, and an archive member comparison. GenericPackHost validates the resulting proof and writes the existing `composition_executed` record to its inherited observer pipe after successful rendering and while that renderer incarnation is still alive. Neither the request child nor the browser receives the observer FD.

The first supported observation route would be Linux, the existing admitted `rendering.timeline_visualize` retained `renderFrames` route, `concurrency=1`, and the registered 2D `TimelineComposition`. This is a proposed support envelope, enabled only after the tests in section 10 establish every link. The ordinary CLI `render` route, CLI sequence fallback, `ThreeTimelineComposition`, unadmitted previews/probes, and other platforms remain **unsupported for this event**. They continue rendering and produce no Composition success event. This explicitly preserves fail-closed T-11 acceptance; it does not make a CLI render qualify. Extending coverage to the CLI would require a separate instrumented browser owner, beyond this smallest change.

Crucially, the frame owner is currently leased only to `rendering.timeline_visualize`, whereas the accepted schema seam observes only `rendering.render`. A visualization frame can prove real Composition execution but cannot be substituted for the required same installed-render operation. This packet does not broaden schema emission to visualization or silently route full renders through the frame owner. With the present front doors, T-11 has no qualifying supported ordinary-render route; closing that remaining product/qualification route requires the explicit M-INT decision in section 9.

The execution witness is a positive engine call count for the actual package function in the rendering page, followed by successful frame/action completion. Loading a module, creating a React element, selecting a Composition, or reporting a screenshot callback alone is insufficient. No JavaScript console message, injected page callback, breakpoint pause, or page-supplied identity is trusted as execution evidence.

| Field | Required authority |
| --- | --- |

| `run_id` | Authoritative admitted kernel ID, `[0-9a-f]{32}`. |

| `pid`, `start_ticks`, `boot_id` | Positive OS renderer PID, Linux `/proc/<pid>/stat` start ticks, canonical lowercase boot UUID; independently mapped from the executing target and still live at emission. These fields never identify the proxy host, Node, or Chrome root. |

Internal admission, evidence and dedup keys do not add wire fields. Schema event semantics, including repeated legitimate schema-consumer events, remain unchanged.

## 4. Trusted per-admission context and bounded deduplication

Create a host-private `CompositionObservationContext` alongside `_HostLease` from authoritative admitted task state. Reuse the provenance of `import_binding`, not the schema seam's `rendering.render`-only capability allowlist. Add private host plumbing for lease ID, executor and immutable render intent where the existing binding lacks them; take those from the retained claim/host, never from frame JSON. It retains runtime epoch, host incarnation, executor/task/run/attempt/lease/fence, immutable render intent, original observer endpoint identity, and a host-generated operation token. Validate the still-current lease at dispatch and finalization. The run ID is never accepted from frame JSON or an environment overlay. The host duplicates its validated pipe write endpoint with close-on-exec, remembers its `fstat` identity and flags, and closes the duplicate on lease retirement. A reused numeric FD cannot change the captured endpoint. The collector's launch association supplies authenticity; these local checks supply continuity only. This is a new optional Composition binding for admitted frame capture; accepted schema emission and its allowlist stay unchanged.

Bind the context to the particular host lease/channel. `_validate_request` remains an exact allowlist; supplying `run_id`, `observer_fd`, an evidence path, or an observation token in client JSON cannot enable observation. The host adds a separate internal observation envelope only after validating the caller's ordinary render request. That envelope contains a fresh per-request nonce, operation token, selected archive/materialization identity, admission generation and host-fixed evidence root. It contains **no observer descriptor**. Node receives it over original private host-owned stdin; it is never merged into `process.env`, props, the public bundle, or the request child's channel. Worker replies carry the nonce/generation; host matches them to the outstanding exchange before accepting proof.

A warm Browser/Node may be reused, but a proof context cannot. New lease: new token, fresh bundle and page, fresh CDP session/coverage, no previous proof or observer. Clear internal state and remove listeners in `finally`; stale/late replies are discarded. A lease for another run cannot reuse old evidence even if inputs and renderer PID match. Context authority remains in the host, not in a warm child's cached environment.

Use a per-admitted-task logical operation key `(runtime_epoch, run_id, task_id, immutable_render_intent)`; attempts, leases, fences, host incarnation, and request sequence are subordinate bindings, not permission to re-emit for retries. Ordinary repeated frame requests and StrictMode/multiple function calls can create witnesses but never a second event. The host stores `OPEN -> PROVED -> WRITE_ATTEMPTED -> SENT|REFUSED` under its lease lock; claim `WRITE_ATTEMPTED` before the syscall. No retry after EAGAIN, short write, lost reply, or ambiguous completion. Until proof succeeds, an incomplete candidate can be replaced by a later valid capture in the same active operation; after write attempt it cannot.

Bound state to at most 64 active observed operations and 256 total operation entries per host; refuse new observation at capacity. Never evict an active/emitted key and then admit a replay. Retire terminal state only when that task's operation is irrevocably closed and its channel cannot submit more work. A subsequent attempt for that task, including after restart or retirement, requires authoritative prior-emission disposition supplied with admission; without it, refuse observation. The collector keeps a bounded campaign receipt keyed by the logical operation and enforces one accepted event across retries/host restarts. This is at-most-once with possible missing observation, not a new durable exactly-once protocol or journal.

## 5. Archive, compiler graph, and byte identity

All formats in this section are proposed retained evidence formats. They do not change a shared contract. Canonical JSON is UTF-8, sorted object keys, compact separators, no NaN/infinities, no duplicate keys; arrays have an explicitly sorted order and integer lengths. Paths use validated POSIX spelling without `..`, NUL, Unicode normalization aliases or duplicate case aliases. Fail observation on ambiguity rather than normalizing it away.

1. **Selected archive A.** Host resolves the actual selected `@banodoco/timeline-composition` archive from the installed renderer's verified package selection, opens a regular no-follow file once, captures raw bytes and SHA-256, and retains them. Never select a similarly named repository archive solely because it exists. Safely read its member map: reject traversal, duplicate members, links and special files. Record package manifest/exports and every member's normalized path, type, size, executable mode and content hash. Compare the package's actual webpack resource bytes to the corresponding archive members, including `package.json`. A source alias escaping that materialization, modified installed member, absent archive, or unprovable archive selection refuses observation. Historical source-build provenance of 0.0.17 remains unproven; this proves only the selected content-addressed archive-to-execution chain.

2. **Compiler inventory G, `astrid-resolved-inputs/v1`.** Append a guarded plugin after `remotionPrimitiveAliasesFor`, retaining its effective resolve configuration. Instrument the actual webpack input filesystem/resource reads and loader dependency reads, retaining the bytes returned to the compiler. Use `NormalModule.getCompilationHooks`, module build completion, `compilation.moduleGraph`, `chunkGraph` and final asset hooks. Record resource identity including query/fragment, issuer/dependency edges, effective export conditions and aliases, loaders and options, captured raw-read hashes and post-loader source hashes, chunk membership, and any generated/virtual module's exact source and producer identity. Flatten concatenated-module membership explicitly. A stats-only dump or post-build directory scan does not satisfy this requirement.

   Record resolver `package.json` reads, build/config/lock/helper inputs, loader implementations and their declared dependencies, `fileDependencies`, `contextDependencies` directory entries, and `missingDependencies` with their observed absent state. Include all resolved code modules in the selected compilation, with the archive-owned Composition subgraph explicitly marked; distinguish compiled, tree-shaken and runtime-loaded members. Public assets copied into the bundle have typed content entries. Each entry states its path root, type, size, executable bits and SHA-256. No uid/gid, access time, mtime, ctime, inode or absolute task-temp path contributes to G; retain those separately for race/ownership checks. Module roots are archive-relative, installed-renderer-relative, or host-admitted pack-root-relative with root identity digests. Arbitrary cwd aliases are not canonical roots.

   Disable webpack bundle/filesystem cache as on current routes, and capture all reads used by loaders; if a loader or native helper bypasses the captured read interface, the adapter must explicitly measure its inputs or refuse. Reads that change under the compiler, uncaptured virtual sources, external code, opaque loaders, and incomplete closure capture refuse observation. The observer must not substitute a convenient whole-directory snapshot for a missed compiler read. Cache disabling and stat-before/after alone do not prove which bytes webpack consumed.

3. **Emitted manifest O, `astrid-emitted-bundle/v1`.** Retain final `processAssets` bytes (after minimization), output-relative paths, types, sizes and SHA-256, chunk/module mapping, G digest, A digest, effective bundler options, exact dependency/tool versions and a source-location witness map. Obtain function ranges in final JavaScript by AST/source-map composition back to the archive's `TimelineComposition` body. Identify by module origin and exact emitted UTF-16 ranges, not by `functionName`. Reject ambiguous/inlined/unmappable functions. Do not change optimization or rebuild a different bundle merely to obtain a witness. O links inputs to the exact output used by this invocation; it does not yet prove loading.

4. **Loaded manifest L, `astrid-loaded-bundle/v1`.** Serve O's retained immutable bytes from a private invocation URL using the existing local serve mechanism; retain each response and record original URL/request/frame/loader IDs separately. The host adapter must verify that the server actually reads those same bytes. A disk directory name is not authority. Enable Network and Debugger before navigation, disable browser cache and bypass service workers for this fresh page. Require successful responses, retained response bodies, and `Debugger.getScriptSource(scriptId)` equality to the corresponding exact emitted JavaScript. Define body hashing over decoded HTTP entity bytes; initially require identity encoding and UTF-8 JavaScript without BOM or rewriting. Retain source text and its UTF-8 hash, plus UTF-16 witness offsets. Capture inline bundle scripts by their exact containing-document ranges. Capture every loaded bundle code/CSS/document asset and dynamically loaded code chunk, correlate to O, and retain evidence of completeness. Media requests are typed separately; they cannot introduce executable code. Browser-driver evaluations from the pinned Remotion/observer code have a separate measured allowlist. Unknown eval/blob/data/remote code, Wasm, unrecognized injected scripts, cache/SW responses, redirects, or missing sources refuse observation.

   L contains A/G/O digests, selected Composition ID, and sorted normalized output-path/role/size/body-hash entries for the loaded bundle resources. It excludes nonce, run ID, PID, wall time, request ID and ephemeral port, which belong to the execution sidecar. Thus L is deterministic for identical loaded bytes and identities. Its hash is the event's `loaded_bundle_identity.sha256`; hashes of O and G can be recomputed without a circular dependency. An emitted but unused lazy chunk remains in O, not falsely listed as loaded in L.

The plugin and read recorder are observational: catch recorder failures and mark proof incomplete while preserving the compiler's original return/error. No evidence failure changes the selected renderer, aliases, output, loader results, encoder, or render decision. Proposed initial observation limits are 20,000 graph nodes, 512 MiB retained input/output blobs, 16 MiB canonical manifests, and 32 MiB trace/CDP data per operation. Overflow closes observation and leaves rendering to its current limits; it never publishes a partial graph as complete.

## 6. Actual execution and live renderer binding

For an admitted supported frame operation, the original Node worker installs a guarded wrapper on that Browser instance's `newPage` **only while `renderFrames` creates its render page**. `selectComposition` runs outside this scope. Require one render page, one main frame and one incarnation; replacement/retry page, browser replacement, process swap or unsupported concurrency disables observation for this operation. Remotion's normal retries/render result remain unchanged.

Before returning the new blank page to Remotion, attach a separate `target().createCDPSession()`. Record target/session IDs and enable Page, Runtime, Debugger, Network, and Profiler. Start `Profiler.startPreciseCoverage({callCount:true,detailed:true})` before navigation. This is engine counting, not best-effort or sampled CPU coverage. Retain `scriptParsed -> executionContextId -> Runtime.executionContextCreated.auxData.frameId`, including unique context ID where supplied. Match that frame to `Page.getFrameTree`. Reject duplicate/cleared contexts or an execution context that cannot be uniquely associated with the main render frame and exact loaded script.

Start target-associated tracing with category `disabled-by-default-devtools.timeline` before navigation. In Chromium 149.0.7790.0, `FillFrameData` writes `frame_host->devtools_frame_token()` and **`process_handle.Pid()`** into metadata. Parse the matching `TracingStartedInBrowser.frames`, `FrameCommittedInBrowser`, and, only with a completed matching pseudo-ID resolution, `ProcessReadyInBrowser` entries. Use `args.data.processId`, never the trace event's top-level `pid` (which can be the browser process emitting metadata), target ID, or `frameTreeNodeId`. Match the frame token to Page/Runtime and its committed invocation URL/loader. Retain complete trace data, `tracingComplete` and buffer-loss status. `SystemInfo.getProcessInfo` must independently list that OS PID as renderer. Enumeration alone cannot map a page to a process.

This trace adapter must be source/version checked and exercised on the installed browser. Missing metadata, pending `processPseudoId`, trace loss, unavailable protocol feature, conflicting frame/process assignments, or an unexpected browser revision means no event. The audited Chromium code establishes the proposed mapping mechanism; no local source audit establishes that the installed browser emitted it.

The host obtains the mapping while the frame is live, opens a Linux pidfd, and samples `/proc/<pid>/stat` and boot ID around that acquisition. Validate the same birth identity on both sides of `pidfd_open`; a PID reused during attachment cannot be accepted. Retain `/proc` status/parent census, executable identity, browser launch/custody identity, PID namespace identity and browser process enumeration. Verify that this renderer belongs to the exact retained Chrome tree. Require same PID namespace visibility, or a separately owner-proven namespace map; the first adapter refuses namespace ambiguity. Do not signal or change renderer custody to observe it.

Before Remotion closes the render page, collect `Profiler.takePreciseCoverage`, `Debugger.getScriptSource`, and outstanding source/Network evidence; end tracing and obtain its complete frame/process metadata while that page is still live. A bounded page-close wrapper starts this capture and then invokes the original close in `finally`; it cannot suppress or replace close. Renderer 4.0.509 does not await these close promises, so the worker must separately track the evidence promise. If tracing is already owned elsewhere, refuse observation without taking it over. Require a positive call count on the outer exact emitted UTF-16 function range of the archive-derived `TimelineComposition`, in that page's default script context, during this capture. Top-level module coverage, a same-named function, metadata-only selection, or coverage from an earlier page is refused. Retain the raw coverage response, range map, context association, frame-completion callbacks and success result. Coverage establishes function invocation; successful rendering of the requested frames and action completion establish that the observation did not come solely from a failed invocation.

At successful Agent render-action completion, before retiring its observation context, the host checks every proof digest, active admission/fence, observer endpoint continuity, pidfd liveness and unchanged `/proc` birth identity again. It validates and retains the completed proof sidecar, samples `monotonic_ns`, and makes the single event write. If the render page has closed but its proven renderer incarnation remains alive, the pidfd and retained execution mapping suffice; if that process exited, refuse. The Browser root's continued existence is not a substitute. A later encode/output failure prevents qualification even if execution happened; the proposed producer waits for successful action completion to avoid emitting for such failed actions.

Source reads, trace/CDP operations and finalization run on bounded observation work, with a 250 ms page-close observation deadline and at most 500 ms total added setup/finalization wait per request. The original page close always runs; no debugger pause, Fetch interception, wait-for-debugger, or collector acknowledgment holds rendering. Timeout, unhandled protocol error, full evidence queue or unfinished proof discards the observation. Deadlines must be tested under disconnect and full-queue faults before enabling this adapter. Precise coverage prevents optimized execution while enabled; this is a real performance cost to measure in the focused proof, and it is active only for an observation-enabled admitted capture.

Include SHA-256 of the final serialized event so the collector resolves that exact line to exactly one proof. Finalize/retain proof before emitting; a failure to retain it suppresses the event.

The collector must obtain these artifacts through an owner-authenticated read path, recompute digests, check event/manifest equality and observe the live renderer independently at collection. Receipt acceptance also requires the authentic `timeline_schema_consumed` event from the **same run**, its own consuming-process identity, installed tuple, Timeline mutation/readback and completed output obligations. The schema consumer and Composition renderer need not be the same PID. A synthetic witness, a missing source blob, an inaccessible artifact, stale admission, collector lag past renderer exit, or unmatched namespace leaves Composition `unobserved`; T-11 stays unqualified.

Retain accepted/refused proof artifacts and raw event framing with the campaign receipt through M-INT review and the qualification retention period; release only after receipt attachment/explicit campaign teardown. Do not use scratch cleanup or warm-worker retirement as implicit permission to delete referenced evidence. Apply hard per-campaign quotas and stop new observation before eviction of referenced blobs. Failed/unsupported observations retain a bounded reason record without creating a success event.

## 8. Explicit refusal behavior and unsupported routes

For the normal CLI path (including `frame_mode` without a retained session), choose `unsupported-route:remotion-cli` before launch, retain that observation diagnostic, and run the existing CLI unchanged. Do not pass the observer to CLI merely to imply instrumentation. No event is emitted on CLI success. For the supported candidate, any missing/mismatched input, process, admission, context, observer or proof produces a diagnostic in the evidence sidecar and **zero** success events, while preserving the normal render result.

Observation failures do not retry a render, change its selected route, kill a browser, change output publication, or poison warm-session cleanup state. Ordinary rendering/cleanup errors still follow their existing product behavior. EAGAIN, EBADF, EPIPE, invalid descriptor type/flags, endpoint replacement, serialization overflow, disk/quota failure, trace loss, timeout and stale nonce are observation refusal. Catch these only in the observation adapter; do not swallow actual renderer exceptions. Diagnostics contain bounded reason codes and identities, never credentials or raw environment values. The collector treats missing or malformed records as unobserved; no refusal is translated into a successful event or a qualification waiver.

## 9. Owner interface decision required

Runtime's accepted change retains `observer_read_fd` on its launch/session handles but does not expose an end-to-end draining/authenticating collector or the new evidence lookup. Do not silently describe those capabilities as implemented. Proposed owner interface, **for review only**:

* M-RT supplies an in-process trusted `attach_render_observer(retained_launch_handle, collector)` attachment before any render admission. It authorizes a single reader of the already-retained endpoint, supplies the verified host incarnation/custody and authoritative claim/lease records, includes collector-backed prior-emission disposition when a task is admitted again, and detaches/drains before handle cleanup. The caller never supplies an FD number, environment value or arbitrary host PID as authority. Failure leaves ordinary rendering operational and qualification unobserved.
* M-QUAL supplies `accept_record(launch_binding, raw_line, receive_monotonic_ns)` and an authenticated read-only `resolve_proof(launch_binding, event_sha256)` lookup of host-sealed artifacts. It checks live renderer identity, admitted operation, exact hashes and its bounded campaign dedup. It must support an Agent-host proxy writing an event whose `pid` names the proven renderer; the sidecar makes this attribution independently verifiable. Lookup is a collector operation, never a synchronous producer acknowledgment.

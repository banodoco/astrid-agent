## 4. Attempt, lease, and terminal protocol

There are four distinct forms of custody: the Runtime task lease `(task_id, attempt_id, lease_id, fence, runtime_epoch)`; a managed-engine admission token; a renderer session's per-task lease; and inherited channels for source, bridge, or observation. A release or acknowledgement for one cannot stand in for another.

The logical attempt sequence is:

```text
claimed → admitted → resources prepared → launched → contained/collected
        → outputs verified → completion reserved → acknowledged completion
        → per-task resources released → scratch disposed or retained

any stage → abort intent → revoke/contain child work → one completion decision
RPC outcome unknown → reconcile exact attempt; retain uncertainty meanwhile
```

The lease observer spans setup, execution, harvesting, upload, and completion. It uses the same absolute execution deadline and acknowledged lease expiry throughout; starting collection cannot reset either. Every heartbeat uses a fresh mutation key and validates returned attempt/fence/epoch/lease identity. A transport exception is not proof of expiry, renewal, stale ownership, or successful settlement. Existing bounded transport/deadline behavior must survive. Stop and join the observer in the outermost finalizer even if reporting or cleanup fails; unresolved remote outcome remains explicit and relies on Runtime fencing/reaping plus reconciliation, not an orphan host heartbeat thread.

`completion_call` is the sole logical completion entry for success, `ensure_failure`, guard abort, cancellation, exception fallback, and cleanup-triggered failure before completion. Its proposed state is `open`, `in_flight(operation, immutable payload/key)`, `acknowledged(outcome, receipt)`, or `unknown(operation, payload/key)`. Under the completion lock, reserve a single operation before releasing the lock for bounded I/O. Other callers join/reuse that decision; they do not issue competing `settle`/`fail`/`cancel` RPCs. Do not hold this lock over blocking RPCs, output hashing, or cleanup: the deadline observer must remain able to set abort intent and contain work.

Before reserving success, recheck deadline, lease validity, cancellation/forced state, child completion, verified output set, and engine identity. Abort winning that reservation prevents success submission. If a success RPC is already in flight when abort arrives, immediately prevent more work and contain owned children; defer any opposite terminal mutation until exact outcome reconciliation. An acknowledged Runtime success cannot be rewritten locally as a newly confirmed Runtime failure. Conversely, an unacknowledged RPC return/exception cannot fabricate success. Record local guard/cleanup facts separately from the confirmed remote outcome. The Runtime remains the authority for which transition actually committed.

On a lost reply, read the exact task/attempt and validate attempt/fence/epoch and completion/output identity before accepting a result. A same-operation replay, if needed, uses the identical payload and existing stable key and counts as the same logical completion. Never respond to ambiguous success by immediately sending `fail` with its different key. If the server cannot establish an exact result, retain `unknown`, emit non-success/unconfirmed evidence using the existing result schema's error/diagnostic facilities, and request reconciliation; do not invent a new public status enum in this task. Runtime capability for this reconciliation is an approval/implementation prerequisite. Definite rejection with proof of no applied mutation can allow a newly arbitrated failure under still-valid authority. Stale authority cannot terminalize a replacement attempt.

`result.json` is one authoritative host receipt path per attempt. Preserve M's atomic minimal receipt before optional evidence and its guarded final enrichment, original coded error and request/parent identity. Repeated writes may replace/enrich that same path; they are not additional Runtime settlement operations. A forced receipt cannot be overwritten by late successful collection. Partial verified outputs on a failed attempt remain evidence, not a second publication; zero-output failure remains explicit. A terminal reporting failure is secondary to the original execution error. If disk I/O prevents a durable receipt, report that limitation rather than claiming it exists. Write available evidence before ephemeral deletion; retain caller-owned/debug/unresolved-custody roots according to their disposition.

## 5. Launch, resource cleanup, and secrets

Establish a finalization scope immediately when child environment/secret state or the first private resource is created. Register every acquired resource before the next fallible operation. Treat argv rewriting, source descriptor preparation, renderer lease acquisition, receipt preparation, payload writes, native spawn, process tracking, import launch observation, and output capture as fallible setup steps in that same scope.

For each actual spawn, build the union of concurrently applicable descriptors: captured external Python source, delegated child bridge, renderer task lease, and child-import observation channel. Preserve each wrapper's admitted interpreter and controls, network startup, UTF-8 flags, and installed/source import rules. Use the platform descriptor/handle translation already used by TLd on Windows; do not expose a Unix FD number as portable authority. Do not add unsupported capability combinations merely to exercise a four-descriptor synthetic launch. Test each supported intersection, especially source+receipt, source+bridge, and source+renderer.

After successful spawn, retain the process's original incarnation and register host custody before `import_receipt.launched`, stream capture, or any optional diagnostic. If spawn raises with `exc.process`, retain and track that original process immediately, then attempt bounded containment; do not claim “never launched.” If proof of absence fails, latch cleanup uncertainty, retain its scratch/identity and prevent a replacement launch or a clean handoff for that affected scope. Do not signal reused PIDs/process groups. A scratch-delete failure with already proven process absence is a separate cleanup failure; it need not invent unknown native custody or block unrelated tasks.

Close the parent's captured-source descriptor in an acquisition-enclosing `finally` after the launch handoff or on any earlier failure. The worker closes its inherited copy after bounded canonical/hash/definition validation. This external-code source descriptor is distinct from `VerifiedTimelineSource`, the private render-data anchor: the latter binds admitted timeline/registry bytes and is handed off only from host-prepared inputs. Preserve its ambient-key clearing and path/digest checks. Neither a receipt nor caller JSON/PYTHONPATH may replace captured code selection or verified timeline authority.

Run containment/stream draining before discarding the redaction material they need. Then finalize the import receipt once, close the task's renderer lease once, revoke/close the child bridge once, and release/fence managed tokens under their existing protocol. A successfully finalized managed token or renderer task lease does not itself settle the Runtime attempt. Shared renderer sessions keep their other live task leases; only the host session owner drains and proves shutdown. Receipt persistence errors are diagnostic and must not mask the action outcome or skip cleanup.

Use nested `try/finally` or equivalent independently registered finalizers so a failure in source closure, output capture, receipt finalization, renderer release, broker stop, or scratch cleanup cannot skip the other obligations. Preserve the original execution exception and structured `code`/`field`/`fix` and attach bounded, redacted reporting/cleanup diagnostics. TLd's `render_failure_message` may add actionable Remotion context; it must not change completion authority or blame an unrelated failure on a backend the host did not select.

The outermost secret finalizer clears every owned copy (`env`, `secrets`, `stream_secrets`, `secret_values`, `worker_env`, `worker_secrets`, and runner environments as applicable), including launch/setup exceptions and exceptions raised by another finalizer. It runs after redaction/draining but cannot be bypassed by them. Restore ambient/global state rather than mutating the caller's mapping. Strip Runtime/child authority from private worker inputs and logs; preserve M's private bridge and scoped workflow execution request. Redact source handoff controls and any credential-bearing exception text. Remove task-created credentials such as `codex-home/auth.json` on force-kill paths as well as normal exit; retained scratch is not permission to retain credentials. Map clearing is reference cleanup, not a claim of secure erasure of Python string memory or an already spawned child's memory.

## 6. Delegation, rendering, and Runtime interfaces

Delegated children use fresh, fenced parent authority and exact child claim/admission. Preserve M's independent child resource reservations and ordinary orchestration parent lease. The child never inherits a general Runtime token or the ability to claim arbitrary queue work. Preserve stage/input-ref/publication metadata, normalized execution requests, and host-selected output roots. Replay is scoped to the same parent attempt and immutable request; changed bytes/selection are refused. Parent success waits for child termination and verified managed outputs; parent lease loss revokes the bridge and contains descendants. Admission/transport ambiguity must not fall back to an ordinary top-level invocation or a queue claim.

In `invocation.py`, combine TLd's `_child_status_error` with M's `_validate_output_page` and `_validate_publication_readback`, including timeout-carried status packets. Validate task/run/attempt association before accepting staged publication. Reject forged rendering source keys and H3 `host_output_root` before either normal or delegated admission. Keep generation/OpenAI normalization and publication intent rules capability-specific; adding native render checks must not remove or apply them indiscriminately to other capabilities.

For native rendering, admission binds exact project/timeline revision, verified media and materialized bytes, execution profile, executable/toolchain, and renderer host lease. Ordinary local/inline inputs retain their existing supported mode checks; they do not mint verified Runtime authority. Source tampering, forged backend source configuration, wrong project/selection, changed helper executable, or a missing admitted lease fails before native work. Preserve ffmpeg/Remotion selection, useful unavailability errors, actual native-descendant containment, and platform-specific descriptor validation. CPU stubs do not establish native rendering acceptance.

`workspace_client.py` forwards exact media selectors, verified reads and M filters to the generated client without silently widening to latest/unfiltered results. A missing generated method is actionable `not_ready`, not permission to use a retired route. The Timeline status reply reports an Agent lock to Runtime `9ef8087…` and a digest mismatch with delivery; this design does not repair or accept that pair. I-AG-02 vendors only an orchestrator-published Runtime SHA; freshness and installed composition provenance belong to the existing finalization tasks.

D4 governs the orchestrator's Runtime decisions after an Astra check; legacy read-only policy is outside this Agent packet. The plan's writer-custody coupling remains an interface dependency: M-RT/I-RT-06 defines requester-bound commit and retired-writer rejection; M-AG/I-AG-09 reconciles the existing Agent assembler and proves requester auth → commit → exact-revision render admission → completion → retrieval. The absent trial `runtime_stitch.py` is not claimed as independently inspected here; I-AG-09 must inspect the available delivered implementation and the integrated route.

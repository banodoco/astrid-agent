# Early interface — R18 lifecycle transfer (03:07Z, provisional)

Manager: relay this interface to M-RT now; it unblocks bounded Runtime work while source reviews continue. This is a design proposal requiring direct protected review, not approval or positive native proof.

**Decision:** Agent owns one durable installation transaction and selected native manager adapter across stop, backup/migration, pointer switch, registration, start, verification and exact prior-state rollback. M-RT owns a long-lived local **TransferSession** that acquires the actual selected realm `owner.lock` nonblocking and RETAINS the successful lock until adoption by the next Runtime or completed stopped-state rollback. `instance.lock` is a publication, not this kernel lock. Never implement an acquire/test/unlock admission, `owner_active=false` clearance, or an isolated positive `down()` return with custody discarded.

Proposed private Python/local IPC API (no bridge change): `begin_transfer(binding, operation_id, expected_phase, manager_evidence)` -> session; `session.admit_stopped_r0(...)` -> HELD proof; `session.arm_start(role, exact_source, selected_definition_digest)` -> one use role ticket; `session.query()` -> monotonic phase/generation; `session.commit_ready(exact_owner, durable_terminal_digest)` -> adoption commit; `session.abort_to_stopped(prior_state_digest)` -> release only after exact restoration/no-live-owner proof. Existing `down(..., transfer=session)` joins the session, never reacquires the broker's mutex or releases its realm fence. API details and error taxonomy will be frozen in DESIGN.md.

Acquire order: installation operation/lifetime locks (Agent's existing authority), Runtime bootstrap mutex, realm directory admission fence, realm owner.lock NB; all unavailable/unknown/replacement cases refuse. Existing live owners use their existing authenticated idle/drain path before any offline owner-lock acquisition. Live R0 with no supported stop handshake remains the canonical running-old refusal; stopped-R0 is the narrow new positive route.

**Unix implementation direction:** authenticated private AF_UNIX session; pass duplicate owner-lock and directory-fence descriptors using SCM_RIGHTS to the exact expected installed candidate process. R1 RealmStore adopts the already-held descriptor instead of reopening/relocking. Every borrowed/adopted alias is close-only (NEVER LOCK_UN); broker retains its alias until exact-ready + durable terminal. This avoids self-deadlock and an unlock/reacquire gap. A session token or JSON receipt alone never proves HELD.

**Windows:** LockFileEx is not assumed transferable by DuplicateHandle. Native positive admission/start remains disabled until a same-process lock-owner continuation or documented/proven native transfer is chosen and reviewed. Existing scheduled-task termination/Job-drain issue is separate and remains blocked; PID fallback, fabricated drain evidence and candidate-only repairs of frozen R0 are forbidden.

**Immediate M-RT units:** (1) retained-session acquisition/state/error types; (2) external-session bootstrap guard so transfer start/down do not reenter held bootstrap mutex; (3) explicit close-only borrowed owner/admission handle support threaded through boundary -> Daemon -> RuntimeService -> RealmStore; (4) exact candidate identity/adoption/health proof; (5) crash/reentry native tests. Agent units: selected-definition/native-census adapters and restart suppression; single transaction session plumbing through stop/backup/migrate/register/start/rollback; exact prior state journal and recovery.

Feasibility checks still open: root replacement while holding the old directory/owner handles, temporary backup/migration Runtime custody, authentic R0 restart during rollback (R0 cannot consume a new descriptor API), macOS complete descendant authentication, and Windows exact-launch durable Job receipt. No native services touched and no full suite prepared.

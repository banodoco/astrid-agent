## 1. Decision, scope, and what can actually work

Use **one durable Agent update transaction plus one retained Runtime TransferSession**. Agent owns selected native service identity, reversible manager state, selection/registration, data policy, rollback, and the durable terminal result. Runtime owns the actual realm kernel lock, idle/work fences, the local transfer process, explicit store-handle adoption, and exact Runtime process/endpoint identity. A successful `Backend.stop()` must return usable retained custody to this transaction; returning a Boolean “stopped” and discarding the fence is insufficient.

The new positive origin is narrowly **authentic R0 already stopped**: exact selected R0 service definition, no live owner or descendant, durable work safe, and successful nonblocking acquisition of the original realm `owner.lock`, retained through handover. Missing discovery is permitted only in this complete conjunction. A live/unknown R0 lacking the required stop capability retains the canonical refusal: “Astrid is still running. Choose Pinokio's Stop button, then try again.” No automatic `up` to recreate discovery, discovery synthesis, new completed-stop receipt for R0, PID fallback, or killing an unvalidated owner.

For Linux/macOS, use actual duplicated POSIX locked file descriptions, transferred to R1 with `SCM_RIGHTS`. R1 adopts that descriptor before touching the database. Broker and every borrower **close aliases without `LOCK_UN`**. A live R1 therefore retains the kernel fence even if the broker crashes. A broker-only lease plus an asynchronous socket watchdog does not have this property and is rejected.

A prior **stopped** R0 is restored to **stopped** on rollback. Do not unconditionally call the current `activate_old()` path. Authentic R0 does not understand an adopted owner descriptor; starting it while the transfer process retains an independently opened lock will self-conflict. Restoring an originally running R0 with uninterrupted lock custody is **unresolved and unavailable**, not silently achieved by unlock/reacquire. A future compatible R0 adapter requires separate protected review; this design neither patches nor wraps R0 to skip its locks.

Windows has two additional unresolved gates: cross-process `LockFileEx` custody cannot use the POSIX assumption, and the frozen hidden scheduled R0 owner has no demonstrated cooperative receipt-completing stop route. The private state machine applies, but its Windows positive start/transfer path returns `unsupported_transfer` before workspace/selection mutation until those gates are proven. Windows negative/refusal behavior is implementable now. This is not a cross-platform fix claim.

## 3. Authority objects and ownership

Name the locks separately:

| Object | Owner and lifetime |
|---|---|
| Existing installer/lifetime locks and `.app-update.lock` | Agent's established operation authority. Retain the existing owner; do not ask a broker to take an independent lock against it. Agent death closes its locks; durable unfinished journal and transfer authority still prohibit ordinary activation. Pinokio's existing lifetime custodian remains separate and is not replaced. |
| Support `runtime/bootstrap.lock` | Transfer process takes it once under existing installation authority and owns it through transaction release/recovery. All session bootstrap/stop calls execute through that holder or an authenticated borrowed guard. Never reenter ordinary `bootstrap()`/`down()` from another process that waits for this mutex. |
| Realm directory admission fence | Transfer process takes the R0-compatible lock on the pinned realm directory, then the realm owner lock. It can lend an alias on POSIX to a selected store; the borrower never unlocks it. Retain until final startup admission/rollback has completed. |
| Realm `<selected-root>/owner.lock` | The actual successful exclusive NB kernel acquisition is the fence. Transfer process retains its original descriptor. A selected R1 borrower receives the same open description; it does not reopen or relock the pathname. Final Runtime retains its alias for its entire writer lifetime. |
| SQLite interruption fence | Existing Runtime lifecycle authority checks durable tasks/attempts/bindings/reservations. It is orthogonal to OS/owner exclusion. End it before waiting for a child DB opener; reacquire/recheck at mutation boundaries while owner exclusion remains held. Never hold its write transaction across an RPC that needs that database. |
| `instance.lock`, discovery, transfer sidecar, journal | Durable publications, not live kernel authority. They bind and reconcile operations but never independently authorize a stop/start/release. |

Installation/operation authority precedes bootstrap → pinned realm directory → owner NB → short SQLite work fence. On contention or query failure unwind only our own newly acquired handles, leave prior publications/data/service intact, and return refusal. Every wait is bounded; no retry converts UNKNOWN to absence. Multi-root operations acquire directory objects in stable `(volume,file-id)` order before owner locks, fail NB rather than invert this ordering, and retain all old handles.

The transfer process is a small installed Runtime control process, outside the old service's cgroup/process tree. It outlives a disconnected Agent controller and accepts exactly one active controller and at most one writer. It is not a newly invented second Runtime daemon. Broker code/executable/version and UID/SID/birth are verified by the controller. It does not inherit bearer credentials or unnecessary file descriptors. Do not put it in a kill-on-exit group belonging to the old service.

## 4. Immutable binding and private API

Proposed module: Runtime `astrid_runtime.lifecycle_transfer`; Agent imports its public private-to-installation facade. It is **not** an HTTP endpoint or change to `POST /v1/update`, app responses, or generated public clients.

`Binding` is a closed versioned object (`astrid.lifecycle-transfer/v1`): operation ID (existing stable outer ID), attempt ID, transfer ID/random generation, controller native identity; installation/program/data/support canonical paths and pinned file IDs; selected realm UUID/root ID and existing owner.lock file ID; old/candidate `Version.document()` and source-profile/manifest/module digests; prior selection/journal digest; native manager kind/namespace/target/effective definition digest; original owner publication statuses/digests and exact original incarnation if known; intended origin (`stopped-r0` or separately supported `live-r1`), prior running/load/enabled state, permitted root lineage and role. `file_id` means device+inode on Unix or volume+file ID on Windows. No paths alone, claimed PID, version label or logical realm UUID substitutes for these identities.

`ManagerEvidence` contains adapter version, manager's native identity/session, exact exported/effective definition and ownership validation result, selected invocation(s), pending jobs/triggers, restart fence result, no-owner/descendant census with collection start/end times and **complete/unknown**, plus compare generation. Runtime checks structure/binding and obtains fresh native identity/lock observations; Agent owns deriving and revalidating the native manager facts. A digest from the driver alone is never proof.

```python
# Proposed exact signatures; opaque local objects, not serializable lock authority.
begin_transfer(paths, *, binding: Binding) -> TransferSession

TransferSession.acquire_stopped_r0(*, manager: ManagerEvidence) -> HeldFence
TransferSession.join_down(boundary, *, manager: ManagerAdapter) -> StopResult
TransferSession.check(*, expected_phase: str, manager: ManagerEvidence) -> SessionStatus
TransferSession.arm_writer(*, role: str, source: SourceBinding,
                           definition_digest: str, journal_digest: str) -> StartReference
TransferSession.writer_closed(*, writer_id: str, proof: NativeCloseProof) -> SessionStatus
TransferSession.record_ready(*, writer_id: str, proof: ReadyProof) -> SessionStatus
TransferSession.commit(*, terminal_journal_digest: str, ready_digest: str) -> SessionStatus
TransferSession.rollback_stopped(*, restored: PriorStateProof,
                                terminal_journal_digest: str) -> SessionStatus
TransferSession.query() -> SessionStatus

# Runtime child entry before bootstrap/RealmStore/credentials/DB admission:
claim_transfer(reference: StartReference, *, source: SourceBinding) -> AdoptedCustody
bootstrap(..., *, transfer: AdoptedCustody | None = None) -> BootstrapResult
down(..., *, transfer: TransferSession | None = None) -> StopResult
```

`begin_transfer` acquires no realm write permission. `acquire_stopped_r0` returns HELD only after the complete §5 conjunction and **after** successful retained native acquisition; it never returns a detached JSON proof as a replacement for session liveness. `join_down` uses the holder's existing guard and short work fence; no nested bootstrap locks or independent RealmStore acquisition. A plain `down` without a session retains current refusal semantics and cannot report the new positive route.

Allowed writer roles: `offline-backup`, `migration`, `candidate`, `rollback-r1`; exactly one claimed/uncertain role at a time. `rollback-r0` is not implemented. `StartReference` is a nonsecret reference to an owner-restricted local endpoint and single-use ticket slot. Secret material is delivered/read through protected local IPC/private capability storage, never command argv, logs, a public receipt, or the bridge. It binds expected native launch and source. Launching through systemd/launchd cannot inherit arbitrary updater FDs; the service connects and requests the actual FD transfer after native membership verification.

Unix transport: owner-only pathname AF_UNIX socket under private support/run storage (use a short secure parent on macOS); bounded 16 KiB framed messages, no trailing frames/unknown fields, NB/deadline/cancellation, constant-time capability verification, monotonic sequence and state CAS. Use `SO_PEERCRED` plus birth/executable/cgroup identity on Linux, audit-token peer identity plus exact launchd target/PID binding on macOS. Verify both peers against frozen native observations. UID and token alone are insufficient to select an incarnation. Protect capability files/no-follow handles and redact all secrets. The isolation boundary is the installation's OS user and trusted installed code, not an adversarial process with arbitrary same-user code/ptrace access; do not claim stronger same-user security than the existing product.

Every mutating request carries `(operation_id, generation, request_id, expected_phase, binding_digest)`. Identical retry returns the recorded result; the same request ID with different bytes returns `binding_changed`. `query` is observational. A different operation/attempt/generation cannot attach or revoke a claimed writer. Refusal result codes are `busy_owner`, `unknown_identity`, `binding_changed`, `incomplete_census`, `restart_unfenced`, `busy_work`, `unsupported_transfer`, `lease_uncertain`, `durability_failed`, `recovery_required`. Include `stage`, whether any owned side effect occurred, and retained recovery identities. Never recast an after-action failure as an initial safe refusal.

## 5. State machine and positive admission

Agent persists every mutation intent before asking the relevant owner to act, then the observed result; fsync and durable replace follow the existing journal policy. Extend `transaction_context.lifecycle_transfer` with versioned references, preimages and phase, rather than introduce a competing terminal journal. Runtime keeps a small durable session ledger bound to that journal. It is not a substitute for a live held descriptor. At disagreement, query both, observe the real native state, and refuse uncertain work.

| Transfer state | Required action and authority | Existing transaction phase |
|---|---|---|
| `OBSERVED` | Read only: exact selection, authentic R0 provenance, supported route, candidate staging/compatibility, private prior-state snapshot, native definition/census. Do not fetch new inputs ahead of interrupted-operation reconciliation. | none / staged |
| `PREPARED` | Existing installation locks held; durable operation intent/preimages; bootstrap serialized. Read-only initial work/census checks pass. Live unsupported R0 refuses before manager stop/data/selection changes. | staged / stopping |
| `HELD_PROVISIONAL` | Pin root and original owner.lock without links/aliases; directory NB then owner NB; retain both; compare path/file IDs and publications again. This proves exclusion, not yet admission. | stopping |
| `RESTART_FENCED` | While locks remain held, compare exact selected definition, install permitted launch gate and reversible native suppression/unload for this **already stopped** target (§8). Observe no pending old launch and complete native absence again. If a process/replacement appears, stop this attempt without signaling it. | stopping |
| `HELD_ADMITTED` | Recheck every predicate below, durable idle/work fence, selection and all native snapshots. Retire only unchanged stale R0 publications under bootstrap guard; preserve their private preimage. No fabricated R0 stopping/completed-stop record. | stopped |
| `PREPARING_DATA` | Optional verified offline backup then candidate-only migration under sequential adopted aliases; no old R0 daemon. Record backup/deltas/root lineage. No final worker/door publication. | backed_up / migrated |
| `SELECTED` | Agent CAS old selection/definition → exact candidate, keeping existing external update guard/operation semantics. Publish candidate registration with authenticated transfer admission; registration may autolaunch on macOS, so arm before bootstrap. | switched |
| `WRITER_CLAIMED` | Exactly selected native R1 process claims once, verifies descriptors and role, adopts before DB/credential/discovery publication. Broker retains aliases. Ordinary starts remain refused. | switched |
| `READY` | Authenticate actual instance/PID/birth/source/realm/door and required services; verify no old tree, one logical owner, matching selected native invocation/definition; short data/semantic checks. | verified |
| `COMMIT_INTENT` | Restore intended persistent enable/load policy against exact candidate, keep successful selected service supervised, retire temporary gates, read back resulting identity. Publish existing durable terminal result. | verified → complete |
| `COMMITTED` | Only after durable complete + ready proof + final process identity, close broker aliases (never unlock) and bootstrap/update control authority. R1 retains owner FD for full lifetime; directory admission is released. Lost reply is handled by query, not another start. | complete |
| `ROLLBACK_INTENT` | Keep all fences and gate, stop only exact admitted candidate/helpers under Runtime custody, wait for complete native close/drain; restore data according to §7 and CAS selection/definition/preimages. | recovering / rollback_selected |
| `ROLLED_BACK_STOPPED` | For stopped-R0 origin, restore exact prior stopped state, durably write rolled_back, then release original locks and gate in safe order (§7). No R0 restart. | rolled_back |
| `RECOVERY_REQUIRED` | Unknown owner/replacement, lost handle authority, incomplete census, failed durability/restore. Retain owned custody if possible; persist unresolved state. Do not mark complete, clear others' records, or launch another writer. | unfinished |

`HELD_ADMITTED` requires **all**: (P1) authentic supported R0 source/selected installation/realm binding; (P2) native exact definition/program/arguments/principal, complete effective configuration and stable object IDs; (P3) positive native absence of old owner **and descendants**, with no unknown visibility; (P4) actual retained NB kernel acquisition of the existing correct owner.lock, post-open root/file checks and unchanged lineage; (P5) effective restart/launch fence plus no queued/alternate managed old invocation; (P6) current work/lease/custody safety under the unchanged Runtime interruption checks; (P7) unchanged or explicitly transaction-authored selection/publications/manager generations; (P8) live authenticated transfer holder and compatible target/rollback plan.

Discovery can be absent and a valid old plain instance marker can persist. Both are observations in the conjunction. Unknown/malformed/foreign marker fields, new discovery, mismatched realm or reused selected process refuse. Do not “heal” conflicting evidence by deleting it. If no current owner incarnation is recoverable, admission relies on exact recorded R0 definition plus a **complete independent** native census bound to its launch scope, not an invented PID from an old log. A platform unable to provide that completeness returns `incomplete_census`.

Each independent missing predicate is a required negative case. In particular: free-then-unlocked probe; lock file absent/recreated; lock busy/error; root rename/symlink/hardlink ambiguity; unreadable native identity/ACL; old owner alive/draining; one surviving child; changed native definition/drop-in/invocation; unexpected same-user owner; candidate wrong source/role/endpoint; new work; stale/replayed capability; lost broker; replacement at any boundary. Refusal preserves replacements and real data and does not issue signals/manager termination on the unknown target.

## 6. Unix process handover, release, and deadlock avoidance

1. Broker opens/pins the selected original owner file and successfully takes exclusive `flock(..., LOCK_NB)`. It retains the descriptor. It does not use `_realm_owner_present()`, whose successful probe explicitly unlocks.
2. After `arm_writer`, exact selected service launches with the ordinary installed interpreter plus the nonsecret transfer reference. It passes launch admission and authenticates locally. Before RealmStore admission it receives exactly the permitted directory/owner aliases through `SCM_RIGHTS`, marks them non-inheritable immediately, checks type/owner/device/inode/root/source/role and authenticated frame. Truncated ancillary data or an extra FD is failure; close all received aliases.
3. A new explicit `AdoptedCustody` path threads through bootstrap → boundary → RuntimeDaemon → RuntimeService → RealmStore. It supplies the existing locked owner file description; `_acquire_owner()` does not open/relock. It borrows directory admission with an explicit lifetime object; no accidental `_release_admission_lock()` unlocks another owner's alias. All existing realm/schema/integrity/work/identity admission checks remain. `acquire_owner=False` is not this API.
4. Every adopted handle has **close-only** disposal for its entire lifetime, including startup exceptions, cancellation, orderly stop, backup/migration completion and final daemon shutdown. Existing `_release_owner()`/offline `_release_offline_custody()` must dispatch on that explicit type. No `LOCK_UN`, conversion to shared lock, generic `file_lock` context manager, or Python wrapper destructor may unlock a shared alias. Never pass the owner alias to worker children. A raw `fstat` is an identity check, not proof that a lock was acquired; the authenticated holder's actual successful acquisition plus descriptor lineage is the authority.
5. Broker closes its aliases only after `COMMITTED` or complete stopped rollback. On successful handover R1's alias remains continuously held. On startup failure R1 closes its aliases after DB close; broker still excludes all ordinary R0/R1 stores. Independent openers using the authentic R0 primitive fail until the last valid alias closes. Ancillary FDs queued in a socket are accounted for; after a lost claim reply, never arm a second writer until the first receiver/queued transfer is resolved and closed.
6. Bootstrap guard is held by broker. A transfer-aware service does **not** call ordinary blocking `bootstrap()` against that lock. Broker executes `_bootstrap_locked` authority actions or lends a non-locking, authenticated guard limited to the selected operation; the child's ready publication is accepted only by this session. Likewise no SQLite write fence is held while waiting on child startup/migration. Never call `backend.runtime(old, 'up')` under the fence.

The Linux [flock manual](https://man7.org/linux/man-pages/man2/flock.2.html) documents shared open-description lock lifetime and the danger of explicit unlock from any duplicate. [Unix socket documentation](https://man7.org/linux/man-pages/man7/unix.7.html) documents descriptor passing. [Apple's XNU flock manual](https://raw.githubusercontent.com/apple-oss-distributions/xnu/main/bsd/man/man2/flock.2) also describes duplicated references and shared explicit-unlock effects. These support the mechanism, not a completed native qualification. Qualify actual supported local filesystems; do not infer the same semantics for unqualified network filesystems.

## 7. Data preparation, failure, rollback, and exact prior state

The prior-state snapshot is private and immutable, integrity-bound to operation/selected roots. Record exact old/candidate Version documents and manifests/module hashes; selection/current pointer and catalog identity/source-profile preimages; installation identity and process-control settings; service-env bytes/mode/ownership; original manager definition/effective overrides, principal, loaded/enabled/disabled/run state and pending invocations; original publication bytes/statuses; pinned root/owner IDs; original semantic project/timeline/media/CAS/sentinel baselines; backup identity/format/schema/digest; and every transaction-authored delta. Raw preimages may contain private configuration and stay owner-restricted. Public proof contains bounded digests/outcomes, not bearer/configuration values.

**Backup/migration:** A `backend.backup()` currently starts authentic old Runtime on Linux/Windows; that would deadlock/conflict with the retained realm fence. Replace that call within transfer mode with an M-RT offline backup utility using a read-only/WAL-aware consistent snapshot under the held owner/directory authority, validated for the authentic predecessor schema. It never boots old R0 or rewrites its database during inspection. Verify retained backup and restore compatibility before destructive migration. Candidate migration uses a sequential R1 borrower with no worker/door readiness and a close-only alias; broker does not permit candidate activation while the helper is live or uncertain. A timeout is failure, not permission to race another helper.

**Same-schema rollback:** preserve the current supported replay/rollback policy for user work written after the version switch. Do not overwrite it with an older backup. Restore version/definition selection while retaining those legitimate writes; retain all existing data and task reconciliation tests. **Schema migration rollback:** use the transaction's verified pre-migration backup under the existing rollback contract, retain the superseded candidate realm and recovery roots, and report any irreversible/post-switch work according to existing policy. Do not redefine migration data-loss rules in this design. If safe exact restore/replay cannot be established, refuse before migration or stay recovery-required; no success/waiver.

**Root-changing restore:** holding a lock on an inode renamed away does not fence a new inode at the same path. M-RT extends the existing Runtime replacement/dirfd machinery to pre-materialize and verify the replacement, lock **both** old and new directory/owner objects, record permitted object lineage, perform pinned parent/name CAS, and retain overlapping custody through startup or rollback. R1 adopts the selected new object's held owner alias. Keep the original object locked until terminal disposition. On rollback restore the exact prior root identity/selection only from this authorized lineage. No general Agent `rmtree`/copy over the live locked tree. Windows open-handle/rename restrictions and its different directory mutex make this transition unqualified there. If a route cannot do overlapping custody, it refuses before data change.

Failure cases:

| Failure boundary | Required action and exact result |

Never resurrect discovery advertising a dead owner as ready. | Prior live R1 rollback | Allowed only for a version that implements adopted custody: stop candidate, restore data/selection, arm exactly one `rollback-r1`, adopt retained lock, authenticate ready, write durable rolled_back, then release broker alias. |

For successful direct update, start/registration is the explicit operation outcome even though R0 was already stopped; restore the intended candidate autostart policy, not the old executable. For **rollback**, prior active/stopped/loaded/enabled dimensions are exact separate fields. For Pinokio, preserve its stopped-user-action semantics and existing lifetime custodian; do not create a login service or automatic foreground start.

### Windows / Task Scheduler and SCM distinction

The available native product adapter is an **interactive-user Scheduled Task**, task path `\\`, name `Astrid Runtime`, least privilege, hidden `pythonw.exe`. It is not an SCM service. Bind task XML/effective action+arguments+working directory, principal SID/logon type/run level, triggers/settings/restart policy/Enabled, task instance GUID/engine process, actual Runtime PID+creation identity/instance, native security descriptors and old pack-host launch UUID. Before any stale host retirement, require the existing producer-authenticated receipt for the **exact original** launch UUID, service/root, native ownership/ACL and receipt lock, `job_drained=true` only after retained Job active count zero and durable replacement completed. Preserve current exact-launch consumer rules and keep replacement receipts separate. R0 `down` can fall back to `TerminateProcess` for a no-console owner; it is not a proven cooperative stop. No late process census can reconstruct a dead producer's private zero-Job witness. The frozen R0 seed remains blocked if that receipt is missing; candidate code cannot cure its history.

Owner locking must use the **original realm file** and R0-compatible `LockFileEx` byte range [0,1), exclusive + fail-immediately. [Microsoft's LockFileEx contract](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-lockfileex) treats the lock as the calling process's and does not grant inherited children access to the locked range. A future positive variant could reserve and then run the final selected Runtime **in the same native service process/thread that acquired the owner lock**, preserving the handle and new store's adopted same-process semantics. An SCM variant, if separately requested, must bind service name/config/binary/security principal, native service instance/process handle and birth, accepted controls, recovery actions/triggers and stopped/pending state. `SERVICE_CONTROL_STOP` requires an authenticated Runtime drain acknowledgment before `SERVICE_STOPPED`; hard termination/state alone is insufficient. There is no source-backed SCM adapter or backward-compatible R0 endpoint in the named tuple. Do not silently create a system service, elevate, migrate the fixture, or claim Task Scheduler evidence qualifies SCM.

## 9. Crash, lost acknowledgment, and reentry

- **Controller dies, broker alive:** broker retains actual locks and forbids new controller/writer by default. Authenticated explicit continuation for the same operation reconciles the existing transaction before downloads/target-equals-installed checks; CAS a new controller generation only after native prior-controller absence. A claimed or uncertain writer remains occupied. No automatic bridge POST.
- **Broker dies before any FD delivery:** no writer was admitted. Kernel locks eventually release; pending journal plus guarded definitions prohibit normal managed launches. Explicit recovery NB-reacquires the real original lock, repeats every predicate and creates a new generation. Stale ledger/sidecar never grants HELD.
- **Broker dies during/after FD transfer:** any DB writer must already hold a real alias. The lock stays held in that process on Unix; ordinary authentic R0/R1 opens fail. The claimant treats socket loss as cancellation and closes the database/workers before its owner alias. Queued FDs/unknown claimant state remain uncertain. A new broker cannot claim absence until actual lock acquisition and complete native census succeed. Same-operation recovery may stop/inspect the exact known writer via existing native Runtime custody; it cannot mint a duplicate alias from a lost broker. Restoring uninterrupted automatic adoption of that live writer is outside the minimal route.
- **Writer dies, broker alive:** broker alias retains exclusion. Socket EOF/process exit is not full descendant drain. Verify Runtime worker/Job receipts and native trees, close all delivered/queued aliases, then mark writer closed and permit one next borrower. If a descendant improperly inherited the lock, real contender probes remain busy; record the leak/refuse, never force-unlock.
- **Lost acquire/claim/ready/commit ACK:** query using the same request/operation/generation. Repeated request returns its durable recorded result; a live/uncertain lease prevents a second launch. Commit failure after durable complete is reconciled from exact ready owner, terminal journal and resulting native definition. Do not roll back a different/new owner or redo migration based on missing reply.
- **Crash between journal and Runtime ledger writes:** each side has intent/result sequence and binding digest. Read both and observe native reality. Completion requires durable Agent terminal plus native outcome; a Runtime ready receipt alone is not terminal. A torn/permission-denied journal or unknown publication yields recovery_required. Only compare-and-delete our generation's sidecars after terminal; preserve replacement publication/manager objects.
- **Both die:** no delegated process can keep writing without its real POSIX owner alias. Managed launch gates survive until explicit recovery and native readmission. If user/manager replaced or bypassed those definitions, fail closed when detected. The protocol does not promise custody against an adversarial same-user program that ignores the advisory lock or deliberately deletes/replaces the locked object.

Release is not “finally unlock”: it is an explicit idempotent terminal transition. Success drops the broker's reference with R1 still holding; stopped rollback closes the final reference only after durable exact restored state and zero writers. Unknown outcomes retain unfinished state and all recoverable data. Evidence follows P13 checkpoint observations; snapshots/polling are never labelled proof of continuous process history. Kernel descriptor lifetime is the mechanism for continuous lock exclusion, independently tested.

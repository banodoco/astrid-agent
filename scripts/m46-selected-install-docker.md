# Selected install diagnostic v2

This is an isolated Linux Actions diagnostic for the fixed V-22 tuple. Dispatch `.github/workflows/m46-selected-install-docker.yml` on the exact runner commit; it checks out that `github.sha`, the four selected source commits, pinokiod `add4a674ad1ba95bb62ec427fce519fe5bf0e9bf` and PTerm `5be43718701c448b43daf0ce51d8935f170065bb`. The workflow writes the request and invokes `python3 scripts/m46_selected_install_docker.py /absolute/request.json`. The v2 request and result schemas define the closed interfaces. A dirty, overlapping or mismatched checkout, non-hosted run binding, or unrecognized source refuses before mutation.

The exact selected Pinokio tree is checked, with a separate immutable closure for install, its static platform/environment helpers, shell helper, and all literal dynamic imports in `lib.js`. The install action's shell bootstrap is pinned to the selected App SHA and its manifest pins Agent and Runtime. The old Agent graph covers different operations and is not used to authorize install. The workflow archives clean source into a unique temporary home and daemon build context, applies the pinned seed compatibility patch and selected engine observation overlay, builds a uniquely tagged image, and launches one uniquely named container with an ephemeral loopback port. The websocket request follows the real PTerm engine dispatch protocol and names `/data/pinokio/api/astrid/pinokio/install.js`, action `run`, and the request ID. The daemon overlay records action resolution. A Node preload records the actual `shell.mjs` bootstrap child spawn and close. The result refuses an observed outcome without matching action resolution, one correlated bootstrap child exit of zero, and valid backend install/version/Node readback; partial readback, bounded raw streams, exits, and hashes remain available on failure. All container and image cleanup is confined to this request's generated names.

The overlay and child instrumentation are diagnostic and writable by the disposable daemon; they are not a protected collector, cannot establish independent custody, and do not authorize an M4-6 slot. `observed` means only those diagnostic action/child/readback predicates were met, not protected settlement. RPC returns, a websocket disconnect, and the client exit are never treated as action settlement. Network downloads and the Docker base/seed dependencies are not all content-pinned; image ID and command logs are retained to make that limitation inspectable. The hosted job retains request, runner identity, result, bounded logs and their hashes even on normal step failure. A job cancelled before its retention step may have only Actions logs.

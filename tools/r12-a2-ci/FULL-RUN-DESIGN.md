# Later A2 groups 019–052: design only

This is not an active workflow or run authorization. Preserve existing 001–018 receipts and the open 015/017 candidate failures. Neither the shakedown nor this design establishes equivalence to the prior host. The existing `full-run-workflow.yml.draft` is an obsolete illustrative option, not an approved trigger.

Evaluate a single separately coordinated, first-creation push on a fresh exact scratch ref. Its frozen run control would bind one immutable manifest SHA, the four fixed Agent/Runtime/VibeComfy/lifecycle tuples, and three fixed group ranges: 019–030, 031–041, 042–052. A 4-side × 3-range matrix produces 12 jobs, with `max-parallel: 4` and `fail-fast: false`. Each job uses its own disposable comparable ubuntu-24.04 runner and per-side checkout, home, temporary directories and environment. Within a job, run groups sequentially with fresh basetemps and isolated receipt paths, preserving selectors, execution mode, test timeouts, complete ID accounting and explicit absences. Setup and pin checks precede group execution; an incomplete setup or coverage result stops later groups in that job. Other jobs may continue and report their own gaps. Any implementation must demonstrate that sequential groups leave no shared mutable test state that invalidates comparability; otherwise use fresh resources or do not count results.

A job ceiling of 360 minutes bounds this design at 4,320 runner-minutes (72 runner-hours) for one attempt across all 12 jobs, plus provider rounding. The ceiling can interrupt a group and leave later groups unrun; no completion is guaranteed. Use separate fixed per-group workflow steps that upload each completed sanitized receipt before starting the next group, so prior receipts survive a later timeout where the artifact service succeeds. Abrupt termination may still lose the current receipt, and missing receipts are gaps. No automatic retry, requeue or second push is included. The runner must enforce the job's fixed side and range, track completed groups, and fail closed on duplicate or incomplete evidence; the workflow must not accept arbitrary refs, shell fragments or selectors.

Before any proposed execution, verify the actual available GitHub Actions quota and its billing period and runner multiplier using the repository/organization's authoritative billing and usage records. Current available quota, billing status, rates, provider rounding, runner capacity and actual durations are unknown. The unpaid exception cannot be assumed to cover a run: require enough verified free capacity for the agreed worst-case bound and any provider rounding, or reduce the bounded scope and seek coordination; do not incur paid usage on an assumption. Record the source and timestamp of the quota check. A 360-minute cap is a proposed resource ceiling, not a change to individual test timeouts or a guarantee of comparability.

The future workflow would require review of exact branch/ref, zero before-SHA, non-forced creation, repository and first-attempt guards, immutable code and inputs, `contents: read`, ephemeral checkout credentials, no secrets, protected artifact paths, and absence of competing push-triggered workflows. Its scratch ref must be verified absent immediately before any authorized creation. Preserve per-group receipts before retention expires. Sanitized receipts omit raw failure messages and cannot alone prove failure-message equivalence or the A2 gate.

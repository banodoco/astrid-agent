# Later A2 groups 019–052: design only

This is not an active workflow or run authorization. Preserve existing 001–018 receipts and the open 015/017 candidate failures. No shakedown or prior-host equivalence is implied. The existing `full-run-workflow.yml.draft` is an obsolete illustrative option, not an approved trigger.

For a future reviewed implementation, use one explicitly coordinated branch-creation event per group, with a unique exact scratch ref and an immutable run-control document binding that event to the frozen manifest SHA, group number, four fixed Agent/Runtime/VibeComfy/lifecycle tuples, and first attempt. Each trigger would run only that one group on four isolated, comparable ubuntu-24.04 hosts, at most four concurrently, with 45-minute job ceilings, unchanged pytest selectors/mode/test timeouts, and fail-closed sanitized receipts. Require the zero before-SHA, no forced push/deletion, repository guard, exact workflow commit, `contents: read`, no persisted checkout credentials or secrets, and verify the scratch ref is absent before its single coordinated creation. Do not automatically rerun or advance to the next group. A timed-out or incomplete receipt remains a gap; decide and separately coordinate any further attempt.

One event costs at most 180 runner-minutes before provider rounding; all 34 groups once cost at most 6,120 runner-minutes (102 runner-hours), plus provider rounding. Actual duration, price, runner availability, billing and quotas are unknown. Individual 45-minute ceilings may interrupt tests and prevent receipt upload. Group sequencing, cost acceptance, receipt retention and any use toward A2 require independent coordination and review. Sanitized receipts omit raw failure messages and cannot alone establish message equivalence or the A2 gate. No branch has been created and no workflow is enabled by this design.

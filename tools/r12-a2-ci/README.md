# R12 A2 no-credit shakedown — draft only

This branch is a handoff, not a run. The sole active draft workflow targets creation of `refs/heads/scratch/r12-a2-shakedown-019-20261111` from zero, in `banodoco/astrid-agent`, on first attempt, with no force or deletion. It executes exactly group 019 on R10, R11, base and candidate, on four separate ubuntu-24.04 GitHub-hosted runners, with `max-parallel: 4`, fail-fast disabled and 45-minute job ceilings. Maximum billed runner time for these jobs is 180 runner-minutes, plus any provider rounding; actual runtime, runner availability, rate, quotas, billing and free entitlement are unknown. No credit or equivalence to the prior host is claimed. A 45-minute ceiling can interrupt setup or a test (whose own timeout remains unchanged); interrupted/absent artifacts are incomplete, not passes. Manual reruns produce skipped jobs due to `run_attempt == 1`. Concurrency prevents overlapping workflow runs; no automatic retry is configured.

A push event uses the workflow file in the pushed commit and branch filters match the pushed ref; unlike `workflow_dispatch`, it does not have the dispatch event's default-branch workflow-file requirement. See [GitHub event reference](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#push) and [workflow dispatch](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#workflow_dispatch). Branch creation must have an all-zero before SHA, and the branch did not exist when checked; verify it remains absent before any future coordinated push. A branch writer can modify the workflow or recreate the branch; these guards are not a security boundary against a malicious authorized writer. Do not push the triggering branch until separately coordinated. Other workflows at the base commit filter their push events to `main`, `release-1`, `int/**`, `windows/**`, or `int/r1`; none match the proposed scratch ref. Repository-level settings or changes after inspection remain unknown.

The frozen manifest and ID inventories are carried here, not prior receipts. Jobs use the exact four Agent/Runtime/VibeComfy/lifecycle pins; Python version is asserted and its executable hash recorded, not compared to an unavailable frozen Python binary hash. Node and esbuild archives and executables are hash checked. `runner.py` checks the workflow checkout SHA, pin locks, versions, Runtime source fixtures, and each side's exact expected ID count/hash. Same pytest flags, selectors, `-rA`, and test timeouts apply. Each job has separate checkout, home, cache, temp and basetemp. Only `contents: read` is granted, checkout does not persist credentials, and test subprocesses receive a sanitized environment. Jobs fetch public repository URLs without configured credentials; if repositories, package dependencies, Python version or Actions are unavailable, setup fails closed. No `.env` files or credential stores are read by this harness. Project tests and dependency installers execute code from the frozen inputs; only run this on disposable isolated hosted runners without secrets.

Each job attempts a 90-day named artifact with initial incomplete marker, setup/pytest logs, pins, hashes, selected/absent IDs, commands, exit and coverage. Status remains incomplete for setup errors or missing IDs; a completed pytest failure remains a failure. Abrupt timeout, force-cancellation, runner loss, failed artifact action or artifact retention expiry may prevent upload; missing artifacts are explicit gaps and no durable receipt is guaranteed. Preserve/download them before expiry. The frozen inventory may contain IDs absent on a side, explicitly recorded; full cross-side message comparison remains required. Prior 001–018 evidence is untouched; group 015 and 017 candidate failures remain open. No gate changes.

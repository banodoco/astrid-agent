Bind the installed-smoke assertions to the *actual product just installed*: record installation path, installed version/identity and a reproducible SHA-256 digest of the installed artifact or defined sorted file inventory, plus how the smoke targets that installation. The Agent `scripts/smoke_wheel_install.sh` by itself builds/installs a wheel and does not establish that binding; adapt the harness without weakening assertions or mark the row blocked if binding is not possible.
2. **`install-update-rollback`** — Use the real isolated direct installation and run the macOS install, update, interrupted-update and rollback journey. Capture exits, service state and installed-product digests before/after each step. If the exact path, prior artifact or interruption mechanism is unavailable, report the missing input and leave the row open.
3. **`app-update-guard-ordering`** — Find an executable assertion for the **installed App** at the pinned revision that tests update guard ordering with an unresolved edit/outbox and observes the actual update request boundary.

No installs, network fetches, large downloads, or tests were run. Source/repository inspection was read-only. The report's “commands/exits” table records inspection commands and the two already-supplied Actions command receipts; it does not represent a fresh non-root run.

## Runtime profile contract and identity binding

Runtime source paths at the exact pin:

- `runtime_protocol/local_worker_composition.py:1253-1360` loads and validates the selected Worker JSON. For `worker_engine` mode it requires absolute existing files for Worker, host, engine, and engine listener; their SHA-256 digests; `machine_id`; loopback engine endpoint/port; `session_config_digest`; profile/release revision and digest fields; absolute existing `source_checkout`, nested `pack_root`, boot-manifest path and hash; and optional capability matrix, environment, and explicit engine launch config.
- `astrid_runtime/bootstrap.py:398-403` requires the source manifest's `worker_profile` to be an absolute, symlink-free existing file. `runtime_protocol/daemon.py:938-941` is the missing-profile rejection observed in Actions.
- `runtime_protocol/local_worker_composition.py:1073-1205` observes live Linux process birth IDs, parent PIDs, UID, process group/session, actual executable path and on-disk digest for Worker, host, engine, and listener. It independently checks listener socket ownership, owner machine ID, and the actual `session/config.json` digest against the selected values. Thus a **valid generated artifact does bind real process identities** when Runtime runs it; declarations alone are not accepted as proof. The supplied successful materializer installs generated only the general Astrid source profile and then hit the missing-profile gate, so none of those process identities was actually bound in either Actions run.
- `pinokio/session.mjs:16-34,37-50,156-160` reads the version record's `profile` and exports it as `ASTRID_RUNTIME_SOURCE_MANIFEST`; supported session options contain only `prepareEditor`. There is no Worker-profile argument/pass-through in this Pinokio pin.

The runtime profile file is an operator/host-specific composition. It is not the VibeComfy source pin, the ComfyUI install receipt, the Astrid source manifest, or a test fixture. Runtime source has a loader and verifier, but no production generator for the host-specific composition. In the supplied installs there is also no `session/config.json`, boot manifest, or Worker profile artifact to hand through the installer.

## Smallest executable route and exact blocker

The smallest eventual path is: (1) run one of the above Pinokio installs on the fresh non-root Linux runner; (2) provision the supported Linux ComfyUI engine with the pinned Agent engine CLI if the target is the generic Linux ComfyUI recipe, or select the corresponding H3 recipe only when that workload and GPU inputs are intended; (3) obtain a real installed Worker/host/engine/listener/session/source/pack/boot composition and produce a Runtime-valid `worker_profile` from those exact target paths and bytes; (4) pass that absolute profile path into the Agent installer so it writes `worker_profile` into the installed source profile before Runtime starts; (5) start Runtime and run the existing R-24 `ensure-worker` path. Steps (3) and (4) do not exist end-to-end in the pinned supplied production route.

Specific unavailable dependency: a Linux provisioning/profile producer (or one genuine target-Linux installation artifact containing the resulting profile and all referenced files), followed by the installer contract to persist/pass its profile path. The Agent install profiles omit the field; Pinokio has no input for it. The exact owner/team for producing the Linux composition is not named in supplied records; installer binding is assigned to M-R1FIX / Agent backend, and profile materialization is M-PIN after that contract exists. Without those pieces there is no honest single command that installs all requested binaries/configuration and emits a profile Runtime will admit. The root-owned inspection host and missing inputs also prevent claiming a fresh non-root validation.

# Pack discovery findings

- **R5, repaired declaration boundary (review 79):** r5-r2 used admitted roots as authority to hash every descendant, including undeclared and authoring-only files. Cache payload inputs now come from canonical resource handles of actually returned packs. Only legacy `content` directory declarations expand recursively; ordinary resource directories remain opaque handles. Authoring exclusions apply inside content directories as well as to direct runtime declarations (direct overlaps still refuse). Canonical declared path/type metadata observes missing-resource repairs, and declared file edit metadata guards prior selection before content reads. Hidden payload edits do not enter that content guard. Ordinary undeclared/authoring file bytes and metadata are absent from cache identity. The existing whole-tree link/escape prohibition remains a separate canonical safety rule: it enumerates names/types solely to identify unsafe paths, whose lexical identities invalidate reuse without reading target bytes.

- **R5, repaired final compatibility closure (review 79):** r5-r2 admitted resource payloads after provisional compatibility, before descriptor failures could quarantine a dependency and its dependents. The loader now checks canonical descriptor identity for all metadata-compatible candidates, then computes compatibility closure before unrelated payload acquisition. Dependencies acquire payloads first; optional read failures remove pending dependents through the existing compatibility validator. Returned scanner order is preserved. Strict/required refusal, quarantine, bundled compatibility exemptions and cycle checks remain with their existing owners. Descriptor rejection necessarily reads the descriptor establishing the error; dependent unrelated payloads remain unopened/unhashed. External metadata discovery retains its existing v2/compatibility behavior. Filesystem guards observe ordinary edits, not an atomic snapshot against concurrent mutation.

- **R5, repaired strict-source invalidation:** r4 omitted source symlink children from cache identity, allowing a warm empty result to hide a newly symlinked pack. The fingerprint now records the link name/type/target and the directory/manifest metadata consulted by the source scanner, without traversing or reading target payloads. Addition, removal, retargeting and target manifest presence changes reach the real strict scanner, which continues to own refusal.

- **R5, alternate-manifest input:** alternate filenames contribute presence/type/link state, which is what canonical refusal consults. Their contents are neither opened nor hashed by the cache. Canonical candidate manifests and schemas retain their content inputs for admission and repair.

- **R4, remaining qualification limit:** focused cache tests isolate filesystem roots and managed inventory with fixtures; they do not qualify installed or remote inventory composition. The existing real local-Git provisioning/discovery test and real support composition test provide local coverage only. Installed-artifact qualification remains unproven in this change.

# Plan 39 per-ID failure ceiling

`required-checks.json` names the complete merge and release job inventories,
using the expanded job names GitHub reports. Matrix children are required in
addition to any aggregate. A missing workflow, skipped job, empty result or
incomplete execution supplies no passing evidence.

The K2/K3 comparator must run from the PR merge base, using that snapshot's
ledger and expected inventory. The candidate supplies proposed data and real
results; it does not approve its own checker, ledger or coverage changes.
The introducing PR has no base checker and therefore fails that trusted step
once under Release 14 Standing ruling 5. Only the Lead installs the accepted
initial policy and configures required checks.

Every ledger entry needs matching G1/G2 native identity, lane, parameters,
failure stage and diagnostic, and a Release 15 owner. Unknown sensitive
custody, persistence, retry and publication failures are excluded. Listed
tests continue executing with their raw outcomes and process exits visible.
Entries can only be retired with passing receipts; they cannot be added,
substituted, or reintroduced after retirement.

The nine missing literal IDs, 33 failing subtests and missing job evidence
must be reconciled before any covered run qualifies as green. An unavailable
baseline remains unknown. A complete recorded run can demonstrate the
comparator; synthetic fixtures demonstrate rejection paths, never product
qualification.
